1. **Educational Structure**: Course, topics, concepts, sections and their hierarchical relationships using specific hierarchical relationship types

**HIERARCHICAL STRUCTURE EXPLANATION**:
The educational content follows a strict 4-level hierarchy with specific relationship types:

**Level 1 - Course**: The entire course/subject (e.g., "Machine Learning Fundamentals", "Database Systems")
**Level 2 - Topic**: Major subject areas within the course (e.g., "Bài 1", "Lesson 1", "Chapter 1") 
**Level 3 - Concept**: Specific learning units within a topic (e.g., "1.1", "1.2", "1.3")
**Level 4 - Section**: Detailed breakdowns within a concept (e.g., "1.1.1", "1.1.2", "1.2.1")

**HIERARCHICAL RELATIONSHIPS**:
```
institution → organization → academicProgram → Course → Topic → Concept → Section
    MANAGES      OFFERS        HAS_COURSE    HAS_TOPIC  HAS_CONCEPT  HAS_SECTION
```

**NUMBERING SYSTEM EXAMPLES**:
```
Course: "Lập trình Java cơ bản"
├── Topic: "Bài 1: Giới thiệu Java" (Course HAS_TOPIC Topic)
│   ├── Concept: "1.1 Lịch sử và đặc điểm Java" (Topic HAS_CONCEPT Concept)
│   │   ├── Section: "1.1.1 Nguồn gốc của Java" (Concept HAS_SECTION Section)
│   │   ├── Section: "1.1.2 Đặc điểm chính của Java"

```

**IDENTIFICATION GUIDELINES**:
- **Course**: Usually mentioned in course title, syllabus header, or main subject name
- **Topic**: Broad thematic areas, often numbered as "Bài X", "Lesson X", "Chapter X" (typically 5-15 topics per course)
- **Concept**: Specific learning units, often numbered as "X.Y" format (typically 3-8 concepts per topic)  
- **Section**: Detailed sub-components, often numbered as "X.Y.Z" format (typically 2-5 sections per concept)

**CONTENT RELATIONSHIP**:
- Each level has content: "content of topic", "content of Concept", "content of Section"
- Content includes the actual learning material, text, explanations at that level using CONTAINS relationship
- Examples, Exercises, Definitions, code belong to the content of their respective level using BELONGS_TO relationship

2. **Learning Components**: Definitions, examples, exercises, and code/formula snippets as distinct entities  
3. **People and Organizations**: Authors, teachers, students, institutions involved
5. **Learning Objectives and Outcomes**: Clearly defined learning goals and expected outcomes for each concept or section
6. **Resources**: Links to external resources, references, or supplementary materials
7. **Dependencies**: Relationships between different components, such as prerequisites or dependencies between concepts or sections
8. **Course Metadata**: Course Description, Course Content, Prerequisites, Course Requirements, Learning Approach, Assessment Methods, Learning Objective, Learning Outcome, Learning Method
9. **Navigation Structure**: Table of Contents, Topic of Table of Contents, Concept of Table of Contents, Section of Table of Contents

**VALID ENTITY LABELS (use exactly these)**:
Course Structure: Course, Topic, content of topic, Concept, content of Concept, Section, content of Section

**VALID RELATIONSHIPS (use exactly these)**:

**Hierarchical Relationships:**
- **HAS_TOPIC**: Course has topics (Course HAS_TOPIC Topic)
- **HAS_CONCEPT**: Topic has concepts (Topic HAS_CONCEPT Concept)
- **HAS_SECTION**: Concept has sections (Concept HAS_SECTION Section)
- **HAS_COURSE**: Academic program has courses (academicProgram HAS_COURSE Course)

**Content Relationships:**
- **CONTAINS**: Parent contains content element 
  * Topic CONTAINS "content of topic"
  * Concept CONTAINS "content of Concept"  
  * Section CONTAINS "content of Section"
  * Course CONTAINS "Table of Contents"
  * Table of Contents CONTAINS navigation elements

- **BELONGS_TO**: Child belongs to parent content
  * "content of topic" BELONGS_TO Topic
  * "content of Concept" BELONGS_TO Concept
  * "content of Section" BELONGS_TO Section
  * Topic BELONGS_TO Course
  * Concept BELONGS_TO Topic  
  * Section BELONGS_TO Concept
  * Example/Exercise/Definition/code BELONGS_TO their respective content level

**Other Relationships:**
- **REFERENCES**: Navigation/index points to content (Topic of Table of Contents REFERENCES Topic)
- **DESCRIBES**: Metadata describes main entity (Course Description DESCRIBES Course)
- **TEACHES**: Instructor relationship (Teacher TEACHES Course)

- **PUBLISHES**: Publishing relationship (Publisher PUBLISHES Course)

- **OFFERS**: Provision relationship (organization OFFERS academicProgram)
- **REQUIRES**: Prerequisite relationship (Course REQUIRES Prerequisites)
- **ACHIEVES**: Goal attainment (Learning Activity ACHIEVES Learning Objective)
- **USES**: Utilization relationship (Student USES Learning Resource, Teacher USES Learning Material, Learning Activity USES Learning Tool, Course USES Learning Platform)
- **SUPPORTS**: Supporting relationship (Learning Resource SUPPORTS Learning Activity, Learning Material SUPPORTS Learning Activity, Learning Tool SUPPORTS Learning Method, Learning Platform SUPPORTS Learning Environment, Reference SUPPORTS Material, Example SUPPORTS Definition)
- **LEADS_TO**: Sequential relationship (Learning Objective LEADS_TO Learning Outcome)
- **IMPLEMENTS**: Technical implementation (code IMPLEMENTS Definition)
- **EXTENDS**: Technical extension (Exercise EXTENDS Example)
- **CONFIGURES**: Technical configuration (Learning Tool CONFIGURES Learning Environment)
- **DEMONSTRATES**: Illustration relationship (code DEMONSTRATES Definition)
- **IMPORTS**: Technical dependency (code IMPORTS Learning Resource)

**STRICT HIERARCHY WITH SPECIFIC RELATIONSHIPS**:
- **Institution Level**: institution MANAGES organization
